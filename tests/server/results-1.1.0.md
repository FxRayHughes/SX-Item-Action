## 本次实际覆盖

- 真实 SX 生成器写入 `SX-Attribute` 当前/最大耐久及截止毫秒；比例原版耐久条正确。
- `<l:CustomDurability>`、`<l:TimeLimit>` 保留位置，重复引用与同行文字正确展开和刷新。
- SX 本地 Random、嵌套计算、原生时间表达式及日期格式器正确运行；旧 Lore 首次初始化、缺少功能时移除变量标记。
- 服务端事件链分发损耗，按事件数值扣减；LOW 提前取消不扣减；其他共享属性及数组保留。
- SX 更新实际修改物品名、Lore 顺序和共享属性，同时保留已消耗耐久、最大值及截止时间；reload 后变量继续可用。
- 客户端执行 repair、durability、timelimit，修复不续期，非法命令不改变主手物品。
- 同编号不同槽位分别过期；末影箱和光标清除过期物品；探针分发过期交互/拾取事件时取消使用并移除掉落实体。
- 不完整 NBT、非法日历日期、时长溢出及同时配置两种期限均被拒绝；损坏状态阻止 update，保留原物品。
- 真实客户端挖掘石块，最终一点自定义耐久耗尽后物品销毁，Bukkit 损坏事件和动作各一次，另一槽位同编号物品仍完好。
- 示例的独立 Kether `import` 脚本输出正确；Kether/Fluxon、共享动作链及事件取消自检通过。
- 旧 SX-Attribute 的原生 Lore 耐久继续作用于其他物品，本插件管理的物品不会重复扣减。
- 完整停服后再次启动，同一件物品仍为 41/100 且保留原截止时间；离线期间到期的另一件在登录后清除。

## 证据与边界

原始日志和逐步 JSON 断言位于指定测试根目录的 `sxia-lifecycle-results/26.2-20260907-200829` 与 `sxia-lifecycle-results/1.21.11-20260907-201003`。构建成功时 Gradle 的 test 任务为 NO-SOURCE，实际回归由本目录的探针、客户端及驱动执行。故意损坏状态和非法配置产生预期警告；最终通过轮次未发现本插件额外异常。26.2 的宿主 Windows OSHI 性能计数器有独立警告。

这不代表 [完整手工清单](../lifecycle-manual.md) 的每个场景都已验证。尚未覆盖全部铁砧/砂轮/修补、护甲承伤、耐久附魔统计、弓/食用/拖拽/数字键边界、所有第三方虚拟容器、所有日期格式及时区组合，或 Folia 区域线程运行。不同服务器仍应按实际插件组合验收。

驱动已关闭本次启动的服务器，并恢复临时替换的插件、配置、脚本与 OP 列表；专用测试账号及证据目录保留。测试中发现并修复了旧 SX-Attribute 重复处理、Kether 示例注释和增量构建版本号问题，最终发布附件与通过测试的哈希一致。
